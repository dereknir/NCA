像素風主視覺 — 四條路線的實物提案

動機:配合下一個未實裝功能,評估整站主視覺像素化。本頁不用文字空談 —— 同一組站台元件(導航/hero/翻譯卡/歌詞行/按鈕)用四種強度各做一份活的 mock, 並附技法實驗室、字型管線實測、以及每頁的遷移成本盤點。往下捲,看完拍板。

① 四個方案 ② 技法實驗室 ③ 字型管線(有地雷) ④ 遷移成本表 ⑤ 我的推薦
先講最重要的實測發現:gacha 現有的像素字型是「歌詞文本」子集 —— 歌詞全覆蓋,但站台 UI 常用字大量缺字(連「詞」「譯」「索」「設」都沒有)。 所以整站像素化必須重建一份站台字集,不能直接搬 gacha 的檔。 本頁用的字型就是我按新管線現做的站台子集(§3 有指令與大小),證明這條路走得通。

每個 mock 都是活的:字型真的是像素字型、按鈕可以按、星星在閃。

強度頁面理由

② 技法實驗室 — 每一招都是可以直接搬走的 CSS

像素邊框三法

① 雙層 box-shadow 描邊
② clip-path 缺角(9-bit 感)
③ 上下錯位硬影(游標懸停試試)
全程無圖片、無圓角。①最便宜;②最有味;③適合強調卡。

硬陰影按鈕 + 按壓位移

box-shadow:4px 4px 0 不模糊 + :active 位移吃掉陰影 = 實體按下去的手感。transition 要設 none,「瞬間」才像 8-bit。

封面抖色(Bayer 4×4 有序抖動)

粒度 6px
canvas 縮小取樣 → Bayer 閾值 → 貼回 image-rendering:pixelated。 方案 A 才用;有動藝人素材的疑慮就止步於 hover 效果。

steps() 打字機(歌詞入場)

CJK 比例字型不能用經典 width steps 法,改 JS 逐字 — 搭 steps(1) 游標。適合翻譯內頁的第一句入場。

掃描線 / CRT 疊層

にしな歌詞宇宙
SCANLINE OVERLAY 2px
repeating-linear-gradient 2px 一格疊最上層。 便宜且可逆 — 加在 hero 一處就有氛圍,別全站鋪(晃眼)。

像素字型 × 尺寸紀律

12px歌詞翻譯 · 巡演設定 · 花絮索引 24px日文歌翻譯 忌 15px非整數倍會糊(對照看) ja 字形触れたら壊れてしまいそうな夜の隙間
fusion-pixel 是 12px 網格 — 只用 12 / 24 / 36px,其餘尺寸必糊。 中日各一檔(zh_hant / ja)按語言掛,漢字字形才正確。

③ 字型管線 — 實測數據與現成指令

覆蓋實測:gacha 子集(歌詞字集)共 1,986 字 — 歌詞樣本 100% 覆蓋, 但站台 UI 測試字串缺「詞譯索絮卡設戰暫略章搭查殼移薦遷」等常用字。 結論:站台像素化要自己的子集。
本頁字型就是新管線的產物(fusion-pixel 2026.07.20 完整字型 → pyftsubset): 站台字集 = 全站 UI 文案 + 導航 + 常用緩衝字 + 假名全表 + ASCII。 woff2 成品:zh_hant 與 ja 兩檔合計約 —(頁面載入時實測), 比 gacha 現行 TTF 子集(484KB)還小。 
# 1. 抽全站會用到的字 (Astro 頁 + public 工具頁全文掃描)
python scripts/build_site_charset.py   # → data/site_charset.txt

# 2. 子集 + woff2 (中日各一檔)
pyftsubset fusion-pixel-12px-proportional-zh_hant.ttf \
  --text-file=data/site_charset.txt --flavor=woff2 \
  --output-file=public/fonts/fp12-site-zh_hant.woff2
pyftsubset fusion-pixel-12px-proportional-ja.ttf ...同上

# 3. BaseLayout 預載 (首屏不閃字)
<link rel="preload" as="font" type="font/woff2" crossorigin
      href="/fonts/fp12-site-zh_hant.woff2">

維運:新增翻譯/新頁面帶進新字 → CI 重跑 charset+subset(掛進現有 workflow 一行的事)。 授權:fusion-pixel = OFL-1.1,gacha 已在用同家族,合規無虞。

⑤ 我的推薦

押 D:分區混搭 — 統一「語彙」,不統一「強度」

這個站的靈魂是「讀翻譯」,全像素(A)會傷到它;輕點綴(C)又撐不起新功能的世界觀。 D 讓遊戲/工具頁全像素、瀏覽頁披像素殼、閱讀區只留簽名 — 三層共用同一組 token(fusion-pixel 字型、硬影、金/藍配色、steps 動畫), 走到哪都認得是同一個站,但每一頁都沒有為風格犧牲功能。

  1. 要你拍板的:路線選哪條(A/B/C/D)?
  2. 若選 D:三層的頁面歸屬照 §①D 的表,還是要調?
  3. 封面圖:保留原圖(我推薦)還是 hover 才抖色?
  4. 字型尺寸紀律:內文像素字只出現在 A 級頁,同意?

拍板後首波交付:pixel tokens(CSS 變數層)+ BaseLayout/global 換裝 + 字型子集管線進 CI — 一個 commit 內全站 B 層生效,A 層工具頁逐一跟上。
