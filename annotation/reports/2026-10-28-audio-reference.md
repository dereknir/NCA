# 音訊比對實驗報告:原曲參考 + shorts 互相參考(2026-10-28)

分支 `feat/reference-align`,**未併入 develop**,也沒有動任何標注資料。程式在 `scripts/experiments/audio_ref/`(實驗用,還沒接進 `auto_annotate.py`)。

## 一句話結論

**同一段錄音的 shorts 很多,直接照抄已審片段的答案,效果遠勝 ASR。**三種方法串起來(同錄音的已審 shorts → 從原曲剪出來的 → 都沒有才用 v3),全部 354 支 golden(留一法):

| | v3 | 新流程 |
|---|---|---|
| **完全不用改** | 38% | **53%** |
| 句子召回 | 90% | **93%** |
| 句子精確 | 97% | 96% |
| 時間 ≤1 秒 | 85% | **92%** |
| 時間差 >3 秒的大錯 | 63 句 | **31 句** |

從零手標的 268 支:完全不用改 34% → 53%。

**影響範圍**:還沒審的 858 支裡,**427 支(50%)**能用音訊比對 —— 166 支找得到同錄音的已審 shorts,334 支是從官方音源剪出來的。

## 1. 原曲參考音訊

- 三張專輯(odds and ends / 1999 / 日々散漫)的歌**全部**在官方頻道找得到官方 MV 或音源,加上單曲與 feat. 共 43 首、44 支(清單 `reference_tracks.json`)。找不到的:うるわしきひと、夜に駆ける、feat. 的 EDEN / Inaho / サンタガール / 水仙 / 夜凪。
- `今日も今日とて remix` 那支只有 63 秒、幾乎沒有人聲,不能當參考;`ワンルーム` 的 Story Video 是 800 秒的劇情片,另外用了完整音源 `oMS1G6dVazE`。
- 官方 MV 都有上傳者字幕,但**日文字幕全部是和弦譜**;中 / 英文是翻譯,而且常把一句拆兩段。拿字幕校正時間反而讓句子精確掉 4 個百分點,**不採用**。

### 整首對齊(`full_align.py`)
整首歌的歌詞順序是確定的,所以改用全域 DP:每一句在轉寫裡找一個遞增的位置、可跳過,對不到的句子依字數比例內插。

- Qwen3-ASR 在 4 分鐘的長音訊上明顯變差(plum 整首只轉出 293 字,whisper 574 字),所以兩份轉寫各自對齊、取對到句數多的當主。
- plum(字幕剛好一句一段)37/37 句,34 句跟字幕差 ≤1 秒。

## 2. 音訊比對(`audio_match.py`)

chroma(12 個音高的能量)互相關,找片段在參考裡的位置與相似度。**同一段錄音 vs 不同演出分得非常開**:

| 比對 | 相似度 |
|---|---|
| MV 片段 vs 原曲(82 支) | 0.99–1.00 |
| 現場片段 vs 原曲(243 支) | 0.81–0.90 |
| 已審 shorts 兩兩(5192 對) | 288 對 ≥0.98,0.94–0.98 之間只有 1 對 |

門檻定 0.95。另外逐 3 秒檢查局部相似度,片段有剪接 / 淡出的地方不套用。

## 3. shorts 互相參考(`eval_peer.py`)

- 已審的 244 支現場片段裡,**127 支(52%)跟另一支已審片段是同一段錄音**(你「常常覺得看過」是對的)。
- 同錄音的不同片段,人工標注彼此差 ≤0.3 秒 —— 照抄非常可靠。
- 有夥伴的 210 支:完全不用改 v3 35% → **63%**,時間 ≤1s 84% → 97%,大錯 43 → 10 句。
- 規則:夥伴的開頭半句(標在 0 秒)只有兩支從同一點開始剪時才照抄;片段結束前 1 秒內才開始的句子不標(人工最後一句離結尾最少 1.02 秒)。

## 4. 原曲參考(`eval_ref2.py`)

原曲時間表 = 整首對齊 + **已審且從原曲剪出的 shorts 的人工時間(取中位數,留一法)**。

- 從原曲剪出的 107 支已審片段:完全不用改 v3 38% → 50%,召回 88% → 96%,大錯 23 → 8 句。
- **但沒有同錄音夥伴、只靠原曲時間表的 30 支,原曲法比 v3 差**(完全不用改 37% vs 50%,≤1s 84% vs 90%)。人工時間池涵蓋到的段落很準;**純自動算的原曲時間表還不夠準**。

## 5. 評分方式的修正

- 副歌一字不差的重複段,人工標第幾次是隨意的(畫面上看起來一樣),評分時視為同一句;同一片段裡第二次出現仍算不同句。v3 也用同一套計分。
- 例外:`KnVgHuaxypc`(あれが恋だったのかな)音訊確定是原曲 21.6 秒的「こんな毎日が」(第 8–10 句),人工標成「あんな毎日が」(第 35–36 句),**很可能是人工標錯**。

## 6. 你要決定的事

**A. 把 shorts 互相參考 + 原曲參考接進正式流程?**
做法:`auto_annotate.py` 跑完後,對每支未審的片段在所有已審 shorts 與原曲裡找同錄音,有就照抄 / 套表(涵蓋不到的段落仍用 v3),結果標來源(annotator 上顯示「🎧 同錄音」)。一樣是 status=auto 待審,不會自動完成。

**B. 要不要確認 43 首原曲時間表?**
全自動的原曲時間表目前不夠準(見 §4)。在 annotator 裡整首確認一次(已預填,每首約 2–5 分鐘),之後 **334 支從原曲剪出來的未審片段**(以及以後新發的)都能直接套用。你審越多 MV 片段,人工時間池也會自動補強這張表。

## 重現方式

```bash
cd ~/NCA
.venv-qwen/bin/python scripts/experiments/audio_ref/dump_ref.py           # 參考音訊整首轉寫 (~30 分, 可續跑)
.venv-qwen/bin/python scripts/experiments/audio_ref/peer.py               # 已審 shorts 兩兩比對
.venv-qwen/bin/python scripts/experiments/audio_ref/eval_combo.py         # 三種方法串起來 vs v3 (golden 354 支)
.venv-qwen/bin/python scripts/experiments/audio_ref/peer_unlabeled.py     # 未審片段能比對到多少
```
參考音訊與字幕在 `~/nca-audio-cache/ref/`(字幕用 `yt-dlp --write-subs --sub-langs "zh-Hans,zh-Hant,en"` 下載),chroma 特徵快取在 `~/nca-audio-cache/feat/`。
